Pilot source update · 10 October 2026

What is in the latest pilot build

The latest local source includes the institution workspace, risk dashboards and a data-connection workflow. Demonstrations use synthetic records. This page describes reviewed source capabilities; a deployment and an institutional acceptance are separate steps.

Nine risk views

Overview, portfolio quality, branches, concentration, liquidity, stress testing, early warning, operations and risk appetite. Trends can use up to 24 supplied month ends. Missing figures keep their reasons rather than becoming zero.

Geographic analysis

Branch records can be grouped and filtered by municipality, district and province using an institution's published location reference. This checkpoint includes geographic rollups and filters. A geographic map renderer and an authoritative boundary dataset have not been verified in this checkpoint.

Data connections and guidance

The signed-in workspace includes connection setup and review, import checks and contextual dashboard guides. A specific CBS product, version and approved interface still need their own integration verification.

Where security features appear

The marketing website explains the service. Institution records and workflow screens are behind sign-in. Backend checks enforce access for each request.

Identity and access

Source includes identity-provider sign-in, second-factor claim checks, institution membership, role permissions and branch scope. Real second-user invitation, rejection, revocation and logout still require independent acceptance.

Review and accountability

Source includes maker/checker workflow, audit records and bounded temporary support access. Production approval requires the institution's security and data-location review.

Dates and reporting

Gregorian civil dates remain the canonical source dates. The AD/BS calendar choice is being integrated. BS conversion, month boundaries and report/export metadata need a verified calendar dataset and range checks before use.

What remains before an institutional pilot

  • Independent checks against the exact final source, including native PostgreSQL and real identity-provider acceptance.
  • Approved CBS access and institution-owned data, calibrated thresholds and confirmed data location.
  • Native review of Nepali and Hindi wording, and verified BS-calendar coverage.
  • A distinct checker and manager for release approval, and measured time savings in each participating institution.

No percentage of labor savings, regulatory acceptance or four-institution production result is claimed. Public-data and synthetic demonstrations do not establish customer validation.
