Risk layer for microfinance institutions

Branch risk monitor, early warning and stress testingbeside your Core Banking System.

CBSRM reads an authorised export from the institution's existing CBS or MIS and turns it into a month-end view of portfolio risk, branch by branch: PAR and overdue migration, concentration, early-warning alerts against agreed thresholds, and stress tests for rate, farm income, monsoon, regional disaster and funding shocks. It is read-only. It posts nothing back and changes no account, so the CBS stays the ledger of record.

01How it connects

CBS versus CBSRM

The CBS keeps the books. CBSRM reads them and tells you where the risk is.

Existing CBS / MIS (export, report or API)
→
CBSRM risk layer
→
Management, board and regulator-oriented reports

CBSRM does not replace the Core Banking System. It analyses authorised data from it.

  • Core Banking System / MISCBSRM risk layer
  • Role CBS / MISRecords transactions, accounts and repayments. It is the ledger of record. CBSRMReads an authorised export of that ledger. It keeps no ledger of its own.
  • Work CBS / MISPosts disbursements, collections and interest, day to day. CBSRMComputes portfolio risk, stress results and early-warning alerts by branch.
  • Access CBS / MISRead and write, inside the institution's own systems. CBSRMRead-only. No posting, no write-back, no change to any account.

02What a pilot looks like

three steps, repeated each month-end

Export, calibrate, review.

  1. 1

    Export

    The institution exports an anonymised or centre-level aggregated portfolio file from its CBS/MIS in the template format (laghubitta_template.csv).

    no customer names or IDs
  2. 2

    Calibrate

    Thresholds, provisioning rates and scenarios are set together with the institution's risk team against current NRB directives.

    set with the risk team
  3. 3

    Review

    Management and board receive the branch risk monitor, alerts, stress results and a board summary each month-end.

    every month-end

04Privacy

processed in the browser

The app processes the file in the browser. Nothing is uploaded.

Where it runsIn the browser tab, on the computer that opens the file.
UploadNone. The file is read locally and is not sent to a server.
What it needsNo customer names or IDs. An anonymised or centre-level aggregated file is enough for the pilot.
What it recordsA SHA-256 of the input file and the parameter set used, so a figure can be traced back to the exact file and settings that produced it. The hash-chained record of every computed block is produced by the open-source library for the sample dataset and shown on the sample dashboard.

05What it gets

try them in the app or see the sample dashboard

Five outputs, every month-end.

Monitor

Branch risk monitor

PAR and a 24 month trend for every branch, filterable by province and district, with overdue migration and concentration across the portfolio.

Alerts

Early-warning alerts

Rules flag branches that cross agreed thresholds, ranked by severity, each with the value and the threshold that triggered it.

06Status

what exists today, and what does not

A working prototype. The institution-specific work is still to do.

  • RunningThe prototype runs end to end on synthetic data: the app, the sample dashboard and the audit trail.
  • Not doneCBS integration is pilot work and has not been done for any institution.
  • Not doneData mapping from an institution's own CBS/MIS export to the template is pilot work and has not been done.
  • Not doneCalibration against current NRB directives is pilot work and has not been done.
  • IllustrativeThresholds and provisioning rates shown in the app and the sample dashboard are illustrative, to be calibrated.
  • Not claimedNo regulatory approval or compliance is claimed. Outputs are not a regulatory report.
